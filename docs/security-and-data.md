# 安全与数据规格

版本：v0.1；更新日期：2026-10-04。本文细化[产品方案](product-plan.md)，规则 `SEC-01` 起供[验收](acceptance.md)引用；工程选择记入[决策记录](decisions.md)。本文维护首版安全设计基线；S1 已开始实现，当前存储映射和实际验证分别见[核心模块](../vault-core/README.md)与[验证记录](validation-s1.md)，其余规则不得视为已经实现或通过。

## 1、威胁模型与保护目标

密码及其关联数据均需保护。其他 APP、文件提供方和登录目标处于独立信任边界。

| 威胁或故障 | 必须控制的结果 | 仍需说明的边界 |
| --- | --- | --- |
| 手机丢失、他人拿到已解锁手机 | 库独立锁定、加密、敏感操作复验 | 设备解锁不等于库授权 |
| 云备份、厂商换机、外流 SDK | 排除数据；禁联网与自动迁移 | 按支持设备实测，不保证全部 ROM |
| 假冒 APP、相似域名、未知 WebView | 验证目标；未知目标不释放凭据 | 接收方后续处理由其负责 |
| 输入法、剪贴板、截图与叠加层 | 减少明文暴露与屏幕防护 | 不保证防外部拍摄或受控系统 |
| 满盘、断电、并发、升级失败 | 无半提交；保留有效库和现场 | 未落盘输入可能丢失 |
| 忘密、设备损坏 | 说明解锁及独立备份条件 | 无后门；同机快照不防设备丢失 |
| 删除、恢复和旧备份误解 | 撤销、覆盖确认及副本说明 | 不保证所有介质物理擦除 |

**SEC-01｜严格本地。** 无云账户、同步、远程解密和云端 AI；Release 合并 Manifest 无 `INTERNET`；无联网分析、崩溃上传、广告、在线字典和远程图标。仍须检查 Intent、provider、日志及备份出口。[Android 网络权限](https://developer.android.com/develop/connectivity/network-ops/connecting)

**SEC-02｜系统副本。** 库、密钥封装、草稿、索引、历史、快照和辅助文件放入私有非备份存储；设置 `allowBackup=false`，覆盖旧备份规则及新版 `cloud-backup`、`device-transfer` 排除规则；适配新迁移模式时补充对应排除。云备份与 D2D 分别实测。官方指出部分 Android 12+ 厂商设备不能只靠 `allowBackup=false` 禁止 D2D；规则缺失也不等于关闭。[Android 数据备份](https://developer.android.com/identity/data/autobackup)

## 2、数据分级与逻辑实体

**SEC-03｜同等保护。** S1、S2 均加密保存、锁定不可见；分级不允许把非密码字段降为明文。S3 必须随库格式评审，不扩展成明文目录。

| 等级 | 内容 | 保存与暴露规则 |
| --- | --- | --- |
| S1 秘密 | 主密码、密码、恢复材料、原文中的秘密、草稿、历史 | 主密码不以可还原明文保存；其余仅在授权动作内解密 |
| S2 敏感元数据 | 名称、账号、网址、标签、备注、时间、内部 ID、状态、目标绑定、活动记录 | 库内加密；不进入系统建议缓存、日志或通知明文 |
| S3 最小识别信息 | 格式标记、版本及格式必需的非秘密解密信息 | 仅保留成熟格式所必需信息；无账号、库名、条目数或明文索引 |

本表的业务元数据指库内保存的内容。文件系统或用户主动导出的位置可能暴露文件存在、大小、修改时间等信息，需在威胁评审中记录；“整库加密”不能被解释成这些外部属性也已隐藏。

下表是逻辑职责，**不是冻结的物理 Schema**。映射到成熟格式或其他评审通过的实现时，不得遗漏保护与生命周期要求。

| 逻辑实体 | 关键内容与关系 | 约束 |
| --- | --- | --- |
| VaultMetadata | 库 ID、内容/保护代次、格式版本、时间 | 与提交一致；可见头部受 S3 限制 |
| Entry | ID、版本、登录方式、原值、状态、删除前状态 | 同平台多身份分别保存；不自动覆盖同名/同账号 |
| SourceNote | 原文、结构化候选、来源片段 | 候选非事实；拆分关联原文，核对前保留 |
| Draft | 目标/新增 ID、基准版本、输入、暂存时间 | 不填充；恢复检查版本；成功落盘才称已暂存 |
| SecretHistory | 条目 ID、版本、旧密码、时间 | 与修改原子提交；恢复为新修改；不直接填充 |
| TargetReference | 条目 ID、种类、展示网址、确认 host/包身份 | 展示值不自动可信；匹配派生值另存 |
| LocalTrust | 安装/设备域、包/签名、验证证据、信任状态 | 本机授权；备份不直接激活；签名沿革待验证 |
| DeviceUnlockBinding | 密钥引用、绑定代次、可用状态 | 无指纹图像；设备密钥不作唯一恢复依据 |
| Snapshot | 内容/保护代次、时间、校验状态 | 验证后才可用；不先删唯一有效副本 |
| BackupOperation | 操作 ID、库代次、目的地、阶段 | 无字段值；生成/验证/异机恢复分记；不推断转存 |
| Activity | 类型、时间、内部 ID、结果 | 加密本地；无敏感值；非防篡改审计 |

**SEC-04｜原值保真。** 账号、密码和主密码不裁剪、不转大小写、不替换空格、不只取首行。匹配与搜索派生值不写回原值；超限明确拒绝或引导分段，不截断。

**SEC-05｜派生数据。** 索引、摘要、缩略图、解析缓存、数据库日志及页面状态纳入落盘扫描；不得为搜索或填充复制明文元数据。搜索仅在授权会话内进行。

## 3、保存与生命周期

**SEC-06｜可验证提交。** 条目、版本、历史、状态及草稿清除一起提交；此前保留旧正式条目。并发按基准版本检查冲突，不静默覆盖；持久化及必要校验成功后才提示已保存。

| 对象/阶段 | 生命周期规则 |
| --- | --- |
| 零散原文 | 完整加密保存；单条整体转换可沿用 ID，多条拆分各获新 ID；所有目标核对前源记录可恢复 |
| 编辑草稿 | 异步加密暂存；锁定立即隐藏；解锁后主动恢复；基准版本冲突先比较；明确丢弃或正式提交后清除 |
| 密码历史 | 按产品方案建议数量保留；修改与历史一起提交；旧值恢复不抹掉后续历史；上限待工程验证 |
| 正常/归档 | 归档停止编辑、复制和自动填充；先取消归档才能恢复这些操作 |
| 回收站 | 保存删除前状态；无查看秘密、复制、编辑或填充；恢复后仍按目标信任状态判断资格 |
| 永久删除 | 清除当前库该条目及关联原文、草稿、历史和索引；现有快照和外部备份可能仍有内容 |
| 快照与暂存文件 | 都加密且排除系统副本；仅删除已核实可再生、无恢复价值的本操作临时产物 |
| 输入文件 | 用户原始便签/导入文件在 APP 外；读取不等于授权删除原文件，也不能声称已清除其其他副本 |

**SEC-07｜锁定优先。** 后台、锁屏、闲置超时或主动锁定立即遮蔽并撤销授权，不为保存延迟遮蔽；已启动写入安全提交或回退。重开只恢复最近成功暂存内容；尽快释放临时明文和密钥，不保证清除所有内存副本。

**SEC-08｜删除真实。** 永久删除、清空历史/回收站重新输入主密码并确认范围；不撤销外部备份、不自动清理故障副本，界面不得声称所有介质已物理擦除。

## 4、主密码与本机授权

**SEC-09｜主密码基础。** 与手机锁屏密码独立；创建确认一致，允许长口令、粘贴及原值输入。门槛、派生算法/参数和库实现待决 D3/D6；不自创密码学。渐进等待不抵抗离线猜测；输错不自动销毁数据。

**SEC-10｜本机便利解锁。** 用户验证主密码后可启用强生物识别；本机受保护密钥与认证解密操作绑定，不仅依赖成功回调。不可用、取消、锁定或绑定失效时回退主密码并保留原库。生物特征/锁屏变化的具体失效行为按选型和设备验证。[Android 生物识别](https://developer.android.com/identity/sign-in/biometric-auth)、[密钥失效规则](https://developer.android.com/reference/android/security/keystore/KeyProtection.Builder#setInvalidatedByBiometricEnrollment(boolean))

| 动作 | 需要的授权 | 作用域 |
| --- | --- | --- |
| 日常查看、编辑、复制 | 当前有效库会话 | 按条目状态执行；锁定即撤销 |
| 自动填充 | 当前请求目标可信、选择条目、本次认证 | 仅本请求账号与密码；不顺带解锁主 APP 会话 |
| 启用/重绑生物识别 | 重新验证主密码 | 当前设备/安装域，不进入备份 |
| 导出、换主密码、永久删除、健康库替换 | 重新输入当前库主密码及操作确认 | 只授权当前操作和选定范围；范围变化重新核对 |
| 只验证外部备份 | 对应备份主密码 | 只读验证，不改当前库、使用时间或授权状态 |
| 损坏库恢复 | 候选备份/快照可完整解密、保全故障文件、确认恢复 | 不要求损坏库先解密；不继承旧授权 |

**SEC-11｜忘记主密码。** 无有效解锁途径则无法重置并保留数据；备份仍需对应主密码。生物识别可继续查看与逐条迁出，但不绕过主密码整库导出或重设。保留原库，不用“找回”包装清空，不增加短 PIN 或远程后门。[KeePass 主密钥](https://keepass.info/help/base/keys.html)

## 5、离线自动填充信任矩阵

**SEC-12｜信任与内容分离。** 名称/网址不证明可信。原生 APP 首次关联需确认真实目标并记录包名、签名；不只比名称或忽略签名变化，签名沿革待验证。官方要求验证包身份；严格离线不能默认为已完成 WebView 在线域名关联验证。[AutofillService](https://developer.android.com/reference/android/service/autofill/AutofillService)

| 请求/信任状态 | 推荐与释放 | 可执行动作 |
| --- | --- | --- |
| 原生 APP 未绑定 | 不自动推荐或释放 | 展示真实包身份，经用户首次确认建立本机关联 |
| 原生 APP 已确认，身份仍匹配 | 可推荐匹配的正常密码条目 | 解锁后由用户选账号；交付前再检查目标 |
| 签名不匹配或验证失败 | 不沿用关联，不释放 | 标为需复核，保留条目；核实前复制回退 |
| 经核验浏览器，可信来源 host 精确匹配 | 可推荐 | 校验浏览器身份与来源，解锁选账号；不自动提交登录 |
| 相似域名、子域名、路径含平台名、未知浏览器 | 不按字符串相似推荐 | 用户另行核对关联；无法可信识别时复制回退 |
| 无法确认域名归属的 WebView | 无候选，不释放 | 手动选条目也不能解除限制；返回 APP 核对后复制回退 |
| 恢复库中的历史关联 | 只作待复核信息，无激活信任 | 当前设备重新验证 APP/浏览器身份与关联 |
| 请求变化、锁屏、认证取消或超时 | 取消本次授权与结果 | 不算成功使用，不交付缓存凭据 |

**SEC-13｜请求绑定。** 仅正常密码登录条目、密码非空且目标可信匹配时填充。授权绑定请求、目标、条目及版本，交付前复核，多账号明确选择。不用无障碍模拟填充、不抓全局剪贴板、不自动登录。

**SEC-14｜恢复不继承信任。** 备份只保留目标描述及关联意图；设备授权、生物识别、浏览器信任和 APP 绑定重新验证。快照恢复同样刷新资格，避免回滚重启已撤销目标；旧备份不自动沿用新设备信任。

## 6、备份与高风险事务

**SEC-15｜出口必须本地。** 导出/恢复只接受已验证的系统本地存储或 U 盘 provider，并核验其身份及根目录；本地性不明拒绝，不设置“忽略并继续”。`EXTRA_LOCAL_ONLY` 只能限制本地可用数据；`FLAG_LOCAL_ONLY` 是 provider 声明，不能独立证明任意第三方实现可靠。不用通用聊天分享或云盘入口。[Intent 本地选项](https://developer.android.com/reference/android/content/Intent#EXTRA_LOCAL_ONLY)、[本地根目录声明](https://developer.android.com/reference/android/provider/DocumentsContract.Root#FLAG_LOCAL_ONLY)

**SEC-16｜导出。** 复验主密码 → 固定库代次 → 生成加密副本 → 校验 → 写入本地 → 验证最终文件 → 记录成功。恢复不依赖旧设备密钥；无明文账号索引或激活设备授权。不标记半文件有效、不覆盖已有文件；说明其他工具后续处理边界。

**SEC-17｜健康库替换。** 完整校验候选及备份密码、预览；非空库可只验证或替换，不自动合并。复验当前库密码、生成并验证保护副本、确认两套密码用途及范围后原子切换；保护失败停止，取消/失败保留当前库，提交后不重复覆盖。

**SEC-18｜损坏库恢复。** 解密失败也可能是密码错，不能直接判损坏；无法区分则合并说明。先完整保全故障文件，不称有效备份；候选完整验证、预览确认后写成独立新库并原子切换。不要求先解密损坏库；无法保全先解决空间，不丢弃现场。

**SEC-19｜主密码修改。** 验证旧密码后创建新保护代次，在独立候选上完成新保护与完整校验；内置快照同步重新保护或淘汰旧口令副本，故障保全副本若无法处理必须明确列为仍可能受旧密码保护的副本。只有新库与快照策略均可提交才切换；随后失效旧会话和生物识别绑定，重新验证新密码并重绑。外部旧备份不被远程撤销，生成新备份后仍须用户管理旧文件。

**SEC-20｜中断恢复。** 导出、替换、损坏恢复、换密、迁移采用可验证阶段：准备 → 候选完成 → 校验 → 提交 → 收尾。检查点无秘密但仍加密；遮蔽优先，重开辨认真正提交点，不按上次进度推断。

| 中断位置 | 重开后的必须结果 |
| --- | --- |
| 提交前 | 原有效库保持可打开；候选不冒充正式库；重新认证后重试或清理本操作临时产物 |
| 切换边界 | 按真实存储结果选择一份完整有效库；不得通过试写覆盖两个候选；具体原子机制待评审 |
| 提交后、反馈前 | 识别已完成，不重复导入/换密；认证后报告实际结果 |
| 新旧库都不能验证 | 保全两者与故障信息，进入恢复；不清空重建或虚报成功 |

## 7、外部边界与工程验证

**SEC-21｜复制与屏幕。** 复制只由用户触发，标记敏感并使用可用清理机制；到期且能确认仍是本次内容才清理，不删除后来复制内容。后台读取受限、进程结束、输入法历史等限制必须真实披露，不保证按时清除所有副本。敏感页面使用 `FLAG_SECURE`、后台预览遮蔽；不承诺防全部录屏或外部拍摄。[剪贴板限制](https://developer.android.com/reference/android/content/ClipboardManager)、[敏感界面防护](https://developer.android.com/security/fraud-prevention/activities)

**SEC-22｜日志与诊断。** 不记录敏感字段、输入值、搜索词、完整 URI、解密异常载荷或密钥。活动仅本地加密；工程日志和崩溃信息使用合成标识与错误类别。APP 不自动对外发送；支持流程不索取真实库或主密码。用户主动登录时目标接收选中凭据，是使用边界，不是授权目标读取整库。

**SEC-23｜密码生成。** 使用 `java.security.SecureRandom`，不使用普通伪随机源、自定义种子或联网服务。按当前生效规则合并互不重叠的 ASCII 字符集，以有界均匀抽样生成指定长度；候选缺少任一所选类型时整条拒绝并重新抽样，直到满足每类至少一个字符。生成前核验长度 8–128 与非空的有效字符组合；高级未填值先按 UX-12 的默认规则解析，不误当作空字符池。生成异常不降级随机源、不使用旧候选冒充成功。

候选与未保存表单同属敏感内存状态，不进入日志、页面 Bundle、磁盘或备份；生成器不把候选写入剪贴板。规则改变后旧候选不可再使用；关闭或锁定时丢弃候选，后台 / 锁定时同时丢弃未保存表单。候选默认隐藏并受约 10 秒显示期限及 `FLAG_SECURE` 保护；隐藏时读屏不暴露候选内容或长度。“使用”只写入表单，正式保存继续使用 SEC-06 的提交与失败回退，不新增持久化旁路，也不保证清除全部运行时内存副本。

| 待验证点 | 必需证据 | 对应决策/规则 |
| --- | --- | --- |
